# OG single-mover port (og-mover-overhaul)

## Reuse
- Porting OG Celeste64 movement/collision to the demake; single-mover vs multi-path collision; controller/mover restructure.

## Learnings
- **One resolver implementation, ordered movement requests**: OG Celeste64 has one `SweepTestMove` implementation, but it can be called more than once in a tick. `StClimbingUpdate` may first call `SweepTestMove(climbDelta, false)` (`Player.cs:1514-1515`); after the state handler returns, `Player.Update` sweeps `velocity * dt` (`:367-371`) and calls one final `Popout(false)` (`:373-374`). The demake now routes both climb and velocity requests through the shared `MoveService` resolver in that order; contacts are not cleared between requests. `movement_contracts_test`, `move_service_smoke`, and real-map guided climb/corner routes cover this structure. Do not mistake “one mover” for one sweep per tick, and do not treat passing fixtures as proof for every mesh edge case.
- **Do not infer formula parity from relocation**: the prior overhaul consolidated movement resolution, but that did not prove every approach/rotate/jump/dash/climb branch matches OG. Compare each formula and its order to the source matrix and require a source-derived fixture before calling it matched; preserve only behavior with explicit evidence.
- **OG Popout wall test is a SEPARATE if**, not an else-after-ground/ceiling: a grounded player running into a wall must still be popped out along the wall normal. Chaining the wall test in the else-chain silently disabled wall popout whenever grounded.
- **Feet-anchored coordinate conversion**: OG stores feet position, demake stores CENTER. Every OG Z-offset must convert (waist = center - half_height + 3), and ground pushout must land the FEET (center' = hit + half_height), not the center.
- **Popout returns true only for wall pops** (drives the resolveImpact-once latch); a ground/ceiling repair alone must not trip it.
- **One-way platforms**: pass-through from below means the floor gate accepts when feet AT/above surface (strict `<` = below = pass-through); the ceiling gate rejects one-ways when feet below the surface.
- **Zero-amount outer move**: OG's ordinary `SweepTestMove` returns immediately for zero delta (`Player.cs:642-645`), but `Player.Update` still runs its separate final `Popout(false)` (`:373-374`) when not in a bubble. The shared C++ path must preserve that final idle popout even when no sweep moved; otherwise resting wall contact can flicker.
- **Skidding is ground-restricted**: entering skid on a fast reverse requires `grounded`; host fixtures must set a real floor plane (not just `grounded=true`) or MovePhase's ray GroundCheck flips grounded false and cancels skid next tick.
- **Host-test migration pattern**: dead motor tests → either delete (pure-motor) or migrate (behavioral) onto `MoveService` + `MovePhase`. Watch for: (a) feet-anchored half_height=10 changes checkpoint y, (b) ground-snap ray is only 5 units (not 50), (c) duplicate link sources in runner cause "multiple definition" — use shared GAMEPLAY_LINK, (d) `Config()` accessor may not exist on controller — use `MoveServiceConfig{}.half_height` or the config struct directly.
- **Run every plan increment's closure gate**: `grep player_motor src/` must return empty after motor deletion — check comments too (update stale `PlayerMotorConfig` comments to `MoveServiceConfig`).
- **Separate movement ordering from input mapping**: the 2026-10-07 report of automatic climb was reproduced as an Ares R-Trigger `Lo` polarity issue (`z=1` at rest; squeezing released it). Corrected to `Hi`, with final captures showing `z=l=r=0` at rest. Diagnose raw device bits before changing climb gates.
- **Do not print a long trace synchronously on climb entry**: the 60-line trace itself caused visible stalls. Normal gameplay leaves detailed tracing off; diagnostic capture stores a bounded in-memory window and drains at most one sample per tick. Profile expensive collision queries independently from trace I/O.
- **Port hitstop at the simulation owner**: OG hitstop freezes the world tick. Zeroing only player velocity or freezing only the controller changes dash momentum and lets actors/platforms continue. The demake now consumes whole fixed world ticks while preserving velocity and timers.

## Increment note — mixed Popout ordering (2026-10-08)

- **Hardest decision:** use deliberately overlapping floor/roof geometry to make the source `if ground / else if ceiling` priority observable, while retaining a separate wall hit; ordinary grounded geometry cannot prove the ceiling branch was skipped.
- **Alternatives rejected:** separate floor, ceiling, and wall fixtures already prove each response, but cannot catch an accidental `else if` around the wall query or a changed ground/ceiling priority.
- **Least confident:** this one simultaneous case does not cover competing wall faces, wall-plus-ceiling without ground, one-way surfaces, or query-ranking parity on arbitrary mesh edges.
